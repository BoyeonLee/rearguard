# PRD: RearGuard

> 스마트폰 카메라 하나로 구현하는 자전거 후방 추월 사고 예방 엣지 AI

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.2 (PoC) |
| 타깃 | 도로를 주행하는 일반 자전거 라이더 |
| 구성 | Android 스마트폰(시트포스트 후방 거치) + BLE 경고 유닛 2종 |
| 단계 | PoC: 주간 도로 환경에서 핵심 기능 검증 |

---

## 1. 제품 개요

자전거 시트포스트에 후방을 향해 거치한 스마트폰이 뒤에서 오는 차량을 실시간으로 인식하고, **얼마나 가까이, 얼마나 빨리 지나갈지**를 예측합니다. 위험한 추월이 예상될 때만 단계적으로 경고하며, 뒤차 운전자에게는 후방 고휘도 LED로, 라이더에게는 핸들 LED와 경고음으로 알립니다.

**포지셔닝:** 레이더는 "뭔가 온다"를 알려주고, RearGuard는 "위험하게 온다"를 알려준다.

---

## 2. 문제 정의

### 2.1 사용자 문제
자전거 라이더는 도로 가장자리를 주행할 때 뒤에서 오는 차량을 볼 수 없습니다. 후방 추돌과 근접 추월(close pass)은 라이더가 대응할 시간이 거의 없는 사고 유형이며, 대형차의 근접 추월은 풍압과 측면 접촉 위험이 특히 큽니다.

### 2.2 기존 해결책의 한계

| 기존 방식 | 한계 |
|---|---|
| 일반 백미러 | 라이더가 계속 시선을 돌려야 하고, 위험 여부는 스스로 판단해야 함 |
| 레이더 후방 감지기 | 거리와 접근 속도만 측정. 차량이 옆으로 얼마나 비켜 추월할지, 차종이 무엇인지 알 수 없어 차량이 많은 도로에서 경고가 과도함 → 경고 피로로 사용자가 경고를 무시함 |
| 녹화형 후방 카메라 | 사고 후 증거용이며 실시간 위험 판단 기능 없음 |
| 공통 | 전용 기기 구매 필요, 가격 부담 |

### 2.3 핵심 문제
> 라이더에게 필요한 것은 "뒤에 차가 있다"가 아니라 "이 차가 나에게 위험하게 지나간다"는 판단이다. 거리 기반 경고는 이 둘을 구분하지 못해 불필요한 경고가 많고, 그 결과 진짜 위험한 순간의 경고까지 무시된다.

### 2.4 해결 방향
- 카메라 영상으로 차량의 종류, 위치, 궤적을 인식해 **예측 측면 간격**과 **충돌까지 남은 시간(TTC)** 을 계산하고, 위험한 추월에만 경고한다.
- 사용자가 이미 가진 스마트폰을 카메라 겸 연산 장치로 사용해 추가 비용을 최소화한다.
- 모든 추론은 기기 내에서 수행해 통신 상태와 무관하게 낮고 일정한 지연시간을 보장한다.
- 거치는 대부분의 자전거에 있는 **시트포스트**에 별도 부품 없이 장착한다.

## 3. 사용자 시나리오

**시나리오 1. 처음 장착**
라이더가 폰·LED 일체형 마운트를 시트포스트에 감아 고정한다. 앱을 켜면 폰의 기울기 센서가 카메라 각도를 자동 측정하고, 라이더는 안내에 따라 장착 높이를 한 번 입력한다. 1분 안에 주행 준비가 끝난다.

**시나리오 2. 안전한 추월 (경고 억제)**
승용차가 충분히 비켜서 추월할 궤적으로 접근한다. 예측 측면 간격이 1.5m 이상이므로 핸들 유닛에 노란 LED만 표시되고 경고음은 울리지 않는다.

**시나리오 3. 대형차 근접 추월 (경고)**
트럭이 라이더 쪽으로 붙어서 접근한다. 후방 LED가 고휘도 점멸로 바뀌어 트럭 운전자에게 라이더의 존재를 알리고, 핸들 유닛은 주황 LED와 짧은 비프음으로 라이더에게 알린다.

**시나리오 4. 충돌 경로 접근 (위험)**
뒤차가 감속 없이 라이더와 같은 선상으로 접근해 TTC가 2초 미만이 된다. 후방 LED가 최대 밝기로 점멸하고, 핸들 유닛이 빨간 LED와 연속 경고음을 낸다.

## 4. 핵심 기능과 구현 기술

### 시스템 흐름

```
[후방: 시트포스트 일체형 마운트]                       [핸들]
스마트폰                                              ESP32-C3
 F4 초기 장착 보정 (최초 1회)                          ├ RGB LED
 F1 차량 인식·추적                                     └ 부저
 F2 위험 추월 예측                                         ▲
 F3 위험도 판단 ──BLE──┬───────────────────────────────┘
                        ▼
              ESP32-C3 + 고휘도 LED (후방 경고등)
```

### F1. 후방 차량 인식·추적
뒤에서 오는 차량을 검출하고 차종(승용차 / 대형차 / 이륜차)을 분류하며, 프레임이 바뀌어도 같은 차량으로 계속 추적한다.

| 구현 기술 | 내용 |
|---|---|
| 객체 검출 | YOLOX-Nano 또는 EfficientDet-Lite0 (Apache 2.0, 상용 출시 시 라이선스 제약이 적음) |
| 모델 최적화 | TensorFlow Lite 변환, INT8 양자화, GPU delegate / NNAPI로 폰 가속기 활용 |
| 데이터 | 공개 데이터셋(COCO 차량 클래스) 사전학습 + 자체 수집 후방 시점 영상으로 파인튜닝, CVAT 라벨링 |
| 객체 추적 | 칼만 필터 + IoU 매칭 (ByteTrack 방식 경량 구현) |

### F2. 위험 추월 예측
추적 중인 차량의 거리와 측면 위치를 추정하고, 1~3초 뒤의 궤적을 예측해 **추월 시 측면 간격**과 **TTC**를 계산한다.

| 구현 기술 | 내용 |
|---|---|
| 거리·측면 위치 추정 | 지면 평면 가정 + 호모그래피: 차량 bbox 하단(바퀴가 땅에 닿는 점)을 실제 도로 좌표로 변환 |
| 추정 보정 | 차종별 평균 차폭 사전정보로 거리 추정 오차 보정 |
| 궤적 예측 | 칼만 필터 기반 등속·등가속 단기 외삽 |
| 위험 지표 | TTC, 최근접 통과 거리(CPA) |

### F3. 3단계 위험도 경고
위험 지표와 차종을 종합해 위험도를 판단하고, BLE로 후방 LED와 핸들 유닛에 전달한다.

| 단계 | 조건 (초기값, 실험으로 조정) | 핸들 유닛 | 후방 LED |
|---|---|---|---|
| 0 안전 | 접근 차량 없음 | 꺼짐 | 기본 점등 |
| 1 주의 | 예측 측면 간격 ≥ 1.5m | 노랑 LED | 기본 점등 |
| 2 경고 | 예측 측면 간격 < 1.5m (대형차 < 2.0m) | 주황 LED + 짧은 비프 | 고휘도 점멸 |
| 3 위험 | TTC < 2.0s 이고 예측 측면 간격 < 0.5m | 빨강 LED + 연속음 | 최대 밝기 점멸 |

| 구현 기술 | 내용 |
|---|---|
| 판단 로직 | TTC + CPA + 차종 가중치 규칙 기반 (판단 근거 설명 가능) |
| 경고 지속 | 히스테리시스 적용으로 단계가 짧은 시간에 오르내리며 깜빡이는 현상 방지 |
| 통신 | BLE GATT, 위험도 단계 1바이트 전송 |
| 하드웨어 | ESP32-C3 ×2, 고휘도 LED, RGB LED, 부저, Li-Po 배터리 |
| 눈부심 방지 | 후방 LED 밝기 상한과 점멸 주기 기준 설정 |

### F4. 초기 장착 보정
시트포스트 높이는 라이더 체격에 따라 달라지므로, 장착 시 카메라 높이와 각도를 보정해 F2의 거리 추정 정확도를 유지한다.

| 구현 기술 | 내용 |
|---|---|
| 카메라 내부 파라미터 | 체커보드 기반 카메라 캘리브레이션 (기기별 1회, 앱에 내장) |
| 카메라 각도 | 스마트폰 가속도 센서(IMU)로 기울기 자동 측정 |
| 카메라 높이 | 사용자가 장착 높이를 1회 입력 |
| 주행 중 보정 | IMU로 각도 변화 감지 시 재보정 안내 |

### 공통 기술 스택

| 영역 | 선택 |
|---|---|
| 앱 | Android (Kotlin), CameraX |
| 학습 | PyTorch |
| 평가 | Python, 통제 실험 (폐쇄 공간 바닥 거리 마킹) |
| 마운트 | 폰·LED 일체형, 회전 방지 고무 패드 클램프 |

## 5. 범위 & 비범위

### 5.1 범위 (PoC)
- F1~F4 핵심 기능
- 주간, 맑은 날씨의 일반 도로
- 시트포스트 후방 거치, Android 기기 1종
- 레이더 방식 대비 오경보 감소 효과 검증

### 5.2 비범위

| 항목 | 이유 |
|---|---|
| 야간·우천·역광 | 별도 데이터와 저조도 대응 필요, PoC 이후 |
| iOS | 단일 플랫폼에서 먼저 검증 |
| 영상 녹화·저장, 클라우드 연동 | 핵심 가치와 무관, 개인정보 이슈 |
| 주행 기록, 지도, 통계 | 핵심 가치와 무관 |
| 보행자·자전거 등 비차량 객체 | 후방 추월 위험의 주 원인 아님 |
| 딥러닝 궤적 예측, 단안 깊이 추정 네트워크 | 모바일 실시간성 부담, 규칙 기반 검증 후 검토 |
| 전동킥보드·공유 PM | 거치 구조와 사업 모델이 달라 향후 확장 |
| 제품 인증 취득 | 출시 단계 과제 |

## 6. 성공지표

### 6.1 핵심 지표
> **레이더 방식 대비 불필요 경고 50% 이상 감소, 위험 추월 감지율 90% 이상 유지**

베이스라인: 같은 데이터에 "거리와 접근 속도만 사용하는 경고 규칙"을 적용해 레이더 방식을 모사한 결과.

### 6.2 기능별 지표 (PoC 목표)

| 기능 | 지표 | 목표 |
|---|---|---|
| F1 | 후방 30m 이내 차량 검출 재현율 | ≥ 95% |
| F2 | 측면 간격 추정 오차 (MAE, 0.5~2.5m 구간) | ≤ 0.3m |
| F2 | TTC 추정 오차 | ≤ 0.5s |
| F3 | 위험 추월(2·3단계) 감지 재현율 | ≥ 90% |
| F3 | 종단 간 지연 (프레임 입력 → LED 점등) | ≤ 200ms |
| F4 | 장착 높이 변경 후 측면 간격 오차 증가 | ≤ 0.1m |
| 공통 | 추론 처리 속도 | ≥ 15 FPS |
| 공통 | 30분 연속 동작 후 FPS 저하 (발열) | ≤ 20% |
| 공통 | 1시간 주행 시 폰 배터리 소모 | ≤ 25% |

## 7. 주요 리스크

| 리스크 | 대응 |
|---|---|
| 폰 발열·배터리 소모 | INT8 양자화, 입력 해상도 조정, 접근 차량이 없을 때 추론 주기 낮춤 |
| 노면 진동·클램프 회전 | 진동 흡수 마운트, 회전 방지 클램프, IMU 기반 재보정 안내 |
| 단안 거리 추정 오차 (경사로, 굴곡로) | 차종별 차폭 보정, 한계 조건 명시 |
| 근접 추월 데이터 수집의 위험성 | 실도로는 자연 발생 상황만 수집, 위험 상황은 폐쇄 공간 통제 실험으로 재현 |
| 사용자 과신 | 보조 장치임을 고지, 동작하지 않는 조건(야간, 우천 등) 안내 |

## 8. ROI

**이미 보유한 스마트폰과 시트포스트를 그대로 활용해 추가 비용을 수만 원대로 낮추면서, 수십만 원대 레이더 제품이 못 하는 '위험한 추월만 골라내는 경고'로 라이더가 끄지 않는 안전 장치를 제공한다.**
