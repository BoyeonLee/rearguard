# RearGuard 현장 조사 결과 보고서 (PoC, 공개 데이터 기반)

## 0. 개발 방향 결정 사항
- PoC는 노트북 Python 환경에서 영상 파일 기반 AI 파이프라인으로 구현
- 모바일 앱은 개발하지 않음 (스마트폰은 최종 제품 구상으로만 남김, PRD 1.2). 보유 기기 iPhone은 테스트 사진 촬영 도구로만 사용
- 물리 출력은 유지: 노트북 → BLE → ESP32-C3 경고 유닛(LED·부저)
- 데이터는 공개 데이터셋 중심, 실제 촬영은 소량 테스트셋에 한정
- 인지와 판단을 분리 검증: 인지(F1, F2의 거리·측면 위치 추정)는 공개 데이터, 판단(F2의 궤적 예측·TTC·CPA, F3)은 합성 궤적 데이터
- 대상: 일반 생활자전거, 시트포스트 높이 후방 카메라, 주간·비 오지 않는 날씨(맑음·흐림), 시내 일반도로

## 3. 카메라 조건
### 3.1 공개 데이터 카메라 (학습·검증)
- 장착 높이: nuScenes CAM_BACK 약 1.57m (nuScenes 체크리스트 14번)
- 해상도·주기: nuScenes 1600×900, 카메라 12Hz, 라벨 키프레임 2Hz (nuScenes 체크리스트 4·9번 확인 완료)
- 흔들림: 거의 없음 (자동차 서스펜션)
- 렌즈 왜곡: 데이터셋 제공 캘리브레이션 값 사용

### 3.2 자전거 높이 테스트 카메라 (트랙 E)
- 기기: iPhone 일반(메인) 렌즈 (촬영 도구로만 사용)
- 해상도·주기: 1080p, 30fps
- 손떨림 보정: 전자식 보정 끔
- 촬영 높이: 60·70·80cm 삼각대 (시트포스트 높이 재현, 기본 70cm)
- 기울기: 약간 아래 (10° 이내)
- 화면 내 가림: 뒷바퀴/펜더 일부, 마운트

## 4. 주행·환경 조건 (목표 사용 환경)
- 자전거 속도: 15~25km/h / 뒤차 상대 속도: 20~40km/h
- 노면: 아스팔트, 요철·과속방지턱 → 진동 존재 (공개 데이터에는 없음)
- 도로: 시내 일반도로, 평지 직선
- 시간·날씨: 주간, 맑음·흐림
- 조명: 역광, 강한 그림자 포함
- 렌즈 오염: 먼지 수준

## 5. 탐지 대상·장면 특성
- 클래스: 승용차(승용+SUV) / 대형차(버스·트럭·트레일러·공사차량·구급차, 전처리 A3) / 이륜차(오토바이+배달 이륜차)
- 검출 목표 거리: 30m 이내
- 동시 차량: 2~3대, 겹침 가끔
- 배경: 도로변 주차 차량 많음, 간판·건물 많음
- 위험 추월 장면: 실데이터에 매우 드묾 → 합성 궤적 데이터로 판단 로직 검증, CARLA는 보류

## 6. 데이터 차이로 인한 주요 이슈 (전처리 설계 핵심)
1. 시점 차이: 학습 데이터 카메라 높이 약 1.57m vs 목표 약 0.6~0.8m
2. 흔들림 부재: 공개 데이터에는 자전거 노면 진동이 없음
3. 도메인 차이: 해외 도로(nuScenes 등) vs 한국 도로, 시뮬레이션 vs 실제 영상
4. 라벨 주기: nuScenes 라벨은 키프레임에만 존재 → 추적·TTC 평가 시 처리 필요
5. 클래스 체계 차이: 데이터셋마다 차량 분류가 달라 3종으로 통합 필요
6. 개인정보: iPhone 직접 촬영분의 번호판·얼굴 비식별화 필요
7. 저장 용량 제약: Drive 15GB 안에서 데이터 선별·압축 필요

## 7. 실시간 처리 목표 (노트북 CPU PoC 기준)
- 처리 속도: 영상 입력부터 위험도 판단까지 파이프라인 전체 15FPS 이상 (CPU에서 미달 시 입력 해상도·추론 주기 조정)
- 경고 지연: 200ms 이하 (프레임 입력 → ESP32 LED 점등)
- 우선순위: 정확도와 처리 속도 균형

## 8. 미확정 사항
- CARLA 진행 여부: 수업 실습 GPU 제공 여부 확인 후, 없으면 GPU 대여 비용 보고 결정
