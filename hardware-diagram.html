RearGuard 하드웨어 설계

RearGuard 경고 유닛을 이루는 부품과 부품 사이의 연결·통신 방식, 위험도별 경고 동작을 정리했습니다. 두 경고 유닛은 같은 XIAO ESP32-C3와 1셀 Li-Po 배터리로 통일하고, GPIO가 감당할 수 없는 부하(파워 LED 300mA, 부저 40mA)는 트랜지스터로 분리했습니다.

① PoC 구성 (노트북)

노트북이 녹화 영상으로 차량 검출·추적·위험도 판단을 하고, BLE로 후방 유닛과 핸들 유닛(XIAO ESP32-C3)에 위험도 1바이트를 보냅니다. 후방 유닛은 AO3400A MOSFET으로 1W 빨강 LED를, 핸들 유닛은 WS2812B RGB LED와 S8050으로 부저를 구동합니다.

② 출시 구상 (스마트폰 앱)

실제 출시는 스마트폰 앱 형태로 구상합니다. 라이더의 스마트폰을 시트포스트 마운트에 후방으로 거치해 카메라 겸 연산 장치로 쓰고, 후방 LED는 마운트에 일체형으로 넣습니다. 폰 후면 카메라와 IMU, NPU로 온디바이스 추론하고 BLE로 후방 LED와 핸들 유닛에 경고를 보냅니다. (PRD 1.2, 개발 범위 밖)

PoC와 달라지는 점

항목① PoC (노트북)② 출시 구상 (스마트폰 앱)
영상 입력iPhone 녹화 파일 → 노트북 (파일 전송)폰 후면 카메라 실시간 (카메라 API, 내부 MIPI CSI)
추론 장치노트북 CPU (ONNX / OpenVINO)폰 NPU·GPU (iOS Core ML / Android LiteRT)
장착 각도삼각대 설정값 직접 입력폰 IMU로 자동 측정 (센서 API), 높이만 1회 입력
BLE 송신Python bleak앱의 BLE Central (iOS Core Bluetooth / Android BLE API)
후방 LED별도 후방 유닛마운트에 일체형으로 내장 (회로는 동일: ESP32-C3 + AO3400A + 1W LED)
핸들 유닛동일 (ESP32-C3 + WS2812B + S8050 + 부저)

후방 LED는 폰 배터리를 쓰지 않도록 마운트에 자체 배터리를 둡니다(1W LED 상시 점등은 폰 배터리 부담이 큼). 출시 구상은 PRD상 개발 범위 밖이므로 사양은 방향 제시용입니다.

Interactive · Warning Behavior

위험도별 경고 동작

뒤에서 차가 다가오는 위험도(0~3)에 따라 후방 유닛과 핸들 유닛이 어떻게 반응하는지 보여줍니다. 단계를 눌러 바꿔 보세요.

후방 유닛 (뒤차 운전자에게)

핸들 유닛 (라이더에게)

위험도후방 유닛 (1W 빨강 LED)핸들 유닛 (WS2812B + 부저)
0 안전30% 밝기로 계속 켜짐꺼짐, 소리 없음
1 주의30% 밝기로 계속 켜짐노랑 불빛, 소리 없음
2 경고70% 밝기로 1초에 2번 깜빡임주황 불빛, 1초에 2번 짧은 삐 소리
3 위험최대 밝기로 1초에 3번 깜빡임빨강 불빛, 끊기지 않는 경고음

XIAO ESP32-C3 펌웨어와 같은 규칙으로 움직입니다. 후방 LED 밝기는 PWM 듀티, 핸들 LED는 WS2812B 색, 소리는 2.7kHz 부저입니다. BLE 연결이 1초 이상 끊기면 후방 LED는 기본 점등, 핸들 LED는 파랑 점멸로 바뀝니다.
