Engineering Deep-Dive

핵심 서브시스템별 기술 접근 방식

F1

차량 인식 및 연속 추적 파이프라인

무엇을

GPU 없는 노트북 CPU에서 15FPS 이상으로 후방 차량(승용차/대형차/이륜차)을 검출하고, 프레임 간 차량 ID를 유지해야 합니다.

어떻게

COCO로 사전학습된 YOLO26n을 nuScenes 후방 카메라 데이터로 Colab에서 파인튜닝합니다. 입력은 416×416 레터박스로 맞춥니다(640과 비교 후 확정). 칼만 필터 기반 추적으로 차량 ID를 유지하고, CPU에서 15FPS를 맞추지 못하면 2프레임에 1번만 검출한 뒤 사이 프레임은 칼만 예측값으로 채웁니다.

F2

위험 추월 기하학 예측 (CPA & TTC)

무엇을

단안(Monocular) 카메라의 원근 깊이 한계를 극복하고 차량의 횡방향 여유 통과 간격(CPA)을 정확히 산출해야 합니다.

어떻게

카메라 광축과 노면 사이의 3x3 평면 호모그래피(Inverse Perspective Mapping) 변환 행렬을 구축하고, 타이어 접지점 바닥 좌표를 실시간 역투영합니다. 등속·등가속 칼만 필터 기반 궤적 외삽을 통해 최근접 통과 거리(CPA)와 충돌 시간(TTC)을 도출합니다. 목표 오차는 측면 간격 0.3m 이하, TTC 0.5초 이하입니다.

F3

단계별 경고 및 초저지연 BLE 통신

무엇을

순간 노이즈로 인한 경고 깜빡임(Flapping)을 방지하고 프레임 입력부터 LED 점등까지 200ms 이내에 경고를 전달해야 합니다.

어떻게

단계가 오를 때와 내릴 때의 기준을 다르게 두는 히스테리시스를 적용해 경고가 깜빡이지 않게 합니다(유지 시간 초기값 300ms, 실험으로 조정). PoC에서는 노트북 Python(bleak)이 위험도 단계를 BLE 1바이트로 보내고, ESP32-C3가 받는 즉시 LED와 부저를 구동합니다.

F4

카메라 장착 높이·각도 보정

무엇을

라이더 체격에 따라 달라지는 카메라 장착 높이와 각도를 반영해, 높이가 바뀌어도 거리 추정 정확도를 유지해야 합니다.

어떻게

렌즈 특성은 체커보드 사진으로 한 번 측정하고, 줄자로 잰 카메라 높이와 삼각대 각도를 입력하면 지면 좌표 변환을 다시 계산합니다. 60·70·80cm 높이에서 같은 위치를 찍어, 높이가 바뀌어도 측면 간격 오차 증가가 0.1m 이하인지 확인합니다.

Data Preprocessing

데이터 전처리 설계: 5개 트랙

nuScenes 공개 데이터로 학습하고, 자전거 높이(70cm)에서 직접 찍은 사진으로 시험합니다. 전처리는 쓰임에 따라 학습 데이터 준비, 실시간 추론, 거리 계산, 판단 로직 검증, 최종 테스트셋의 다섯 트랙으로 나뉩니다.

C

거리 추정 기하 전처리

매 프레임

AI가 찾은 차의 진짜 거리 계산하기 → 거리·측면 위치 (F2)

D

합성 궤적 데이터

판단 로직 검증 (F2·F3)

안전 추월 · 근접 추월 · 충돌 경로 · 정지 차량 4개 시나리오를 15FPS 궤적으로 각 200개씩 균형 있게 생성합니다. 노이즈 없는 궤적에서 정답 TTC·CPA를 계산한 뒤, 위치 흔들림(σ 0.3m), 검출 누락 5%, 추적 ID 뒤바뀜 2%를 주입해 "시력이 약간 나쁜 상태"에서도 판단이 맞는지 시험합니다.

E

자전거 높이 테스트셋

최종 시험지

iPhone을 70cm 높이 삼각대에 두고 주차 차량을 뒤쪽 5~30m × 옆 0.5~2.5m 격자로 30장 촬영하고, 60·80cm 높이에서 같은 위치 12장을 더 찍어 높이 변경 영향을 확인합니다. 거리는 차량 앞면 바닥 기준으로 실측하고, 번호판·얼굴은 흐림 처리합니다. 트랙 B·C와 같은 전처리로 평가하며 학습에는 절대 쓰지 않습니다.

실용성과 신뢰성을 우선시한 핵심 아키텍처 선택 배경입니다.

device_hub Q1: 왜 노트북에서 검증하는가?

이 프로젝트의 목적은 PoC(개념 검증)입니다. 앱 개발 없이 노트북 Python(CPU)에서 영상 입력 → 검출 → 거리 계산 → 위험도 판단 → ESP32 경고등까지 전체 흐름을 검증합니다(15FPS, 200ms 이하). 안전 경고는 지연이 짧고 일정해야 하므로 클라우드가 아닌 로컬 기기에서 추론합니다. 최종 제품은 라이더가 이미 가진 스마트폰을 시트포스트에 거치하는 형태로 구상하지만, 이번 개발 범위에는 포함하지 않습니다.

pedal_bike Q2: 왜 짐받이가 아닌 시트포스트인가?

로드바이크, 그래블, MTB 등 대다수 현대 스포츠 자전거는 짐받이 아일렛이 없어 추가 프레임 설치가 사용자에게 큰 마찰이 됩니다. 시트포스트는 모든 자전거에 공통 존재하는 표준 규격이므로 접근성이 극대화됩니다. 라이더마다 달라지는 카메라 장착 높이와 각도는 입력값으로 지면 좌표 변환을 다시 계산해 소프트웨어에서 보정하고, PoC에서는 60·70·80cm 높이 사진으로 이를 검증합니다.

account_tree Q3: 왜 딥러닝 궤적 예측이 아닌 규칙 기반인가?

안전 직결(Safety-Critical) 시스템에서는 오작동 시 원인을 즉시 규명할 수 있는 해석 가능성(Explainability)과 엄격한 결정론적(Deterministic) 상한 지연 보장이 최우선입니다. 또한 연산 자원을 객체 검출에 집중시킬 수 있고, 칼만 필터와 CPA 기하학 규칙은 합성 궤적 데이터로 시나리오별 정답과 바로 비교해 검증할 수 있습니다.

terminal Q4: 왜 이 검출 모델(YOLO26n)인가?

CPU 속도 공식 측정값이 있는 후보 중 가장 정확합니다(COCO AP50-95 40.9, CPU ONNX 38.9ms, 640 입력 기준). 작은 물체 검출 기능을 공식적으로 내세워 30m 거리의 작은 차량 검출에 유리하고, NMS가 없어 차가 여러 대 보여도 처리 시간이 거의 늘지 않습니다. 적은 데이터로 파인튜닝하기 쉽고, Colab 세션이 끊겨도 이어서 학습할 수 있습니다. 출시 계획이 없는 PoC이므로 라이선스는 선정 조건에 넣지 않았습니다.
